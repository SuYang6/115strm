# GitHub 发布与宝塔点击更新

代码仓库：https://github.com/SuYang6/115strm

镜像：`ghcr.io/suyang6/115strm:latest`，支持 Linux ARM64 与 AMD64。提交到 main 或在 Actions 页面手动运行 `Build and publish Docker image`，通过前端构建和 Go 测试后发布 latest；版本标签 v* 另生成同名镜像标签和固定提交镜像标签。标签发布不会把旧代码覆盖到 latest。

## 第一次配置

1. 等待仓库 Actions 首次运行成功。
2. 在 GitHub 账号的 Packages 中找到 115strm，将包可见性设为 Public，服务器才可免登录拉取。代码公开与镜像公开是分别设置的。
3. 服务器现有配置 `/opt/panstr-src/deploy/config.yaml` 保持原样。只需要一次下载更新脚本和镜像版 Compose：

```bash
cd /opt/panstr-src
sudo curl -fL https://raw.githubusercontent.com/SuYang6/115strm/main/scripts/update-image.sh -o scripts/update-image.sh
sudo curl -fL https://raw.githubusercontent.com/SuYang6/115strm/main/deploy/docker-compose.registry.yml -o deploy/docker-compose.registry.yml
sudo cp -p deploy/docker-compose.yml "deploy/docker-compose.yml.before-registry-$(date +%Y%m%d-%H%M%S)"
sudo cp -p deploy/docker-compose.registry.yml deploy/docker-compose.yml
sudo bash scripts/update-image.sh
```

每条 curl 命令成功后再继续；若之前自定义了端口、用户或额外挂载，请将备份 Compose 中的自定义值合并到镜像版。首次切换沿用当前容器的 Compose project 名称，保留 115strm 容器名、998:999 用户、8585/8097/8590 端口与 panstr 数据目录。

## 在宝塔添加按钮

在宝塔“计划任务”添加 Shell 任务，名称填“更新 115strm”，执行内容填：

```bash
bash /opt/panstr-src/scripts/update-image.sh
```

该任务以 root 执行。关闭周期自动执行，需要升级时手动点击“执行”；不同宝塔版本的停用和手动执行行为可能不同，应以当前界面为准。若停用后无法手动执行，则在执行后重新停用，避免定时更新。更新结果查看任务执行日志。

以后发布新代码、等待镜像构建成功，再点击该任务的“执行”。不上传 ZIP、不在服务器编译、不修改运行配置。

脚本只备份运行配置 `deploy/config.yaml` 和部署配置 `deploy/docker-compose.yml`，写到 `/opt/panstr-backups/`。然后拉取镜像、重建容器并检查 8585 健康接口；拉取失败不停止旧服务。按用户要求，不备份数据库、Cookie、回收站，也不额外保留旧镜像标签；配置备份无法恢复数据库内容或撤销数据库迁移。已有数据备份不会自动删除。

## 公开范围

运行配置、数据库、Cookie、日志、初始管理员密码、ZIP、旧 diff 和个人交付记录不提交。示例中的认证字段为空。项目自带的目录 CID 示例需要按用户自己的目录调整，不提供任何账号访问权限。GitHub Actions 使用平台自动提供的 GITHUB_TOKEN 发布镜像，无需将 Token 写进代码。
